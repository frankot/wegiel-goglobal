1. Streszczenie projektu

System informatyczny służący do obliczania, monitorowania i raportowania śladu węglowego przedsiębiorstwa GO GLOBAL GROUP, zgodnie z metodyką GHG Protocol (Greenhouse Gas Protocol).

ZakresOpisPrzykłady
Zakres 1 Emisje bezpośrednie ze spalania paliw Kotły, piece, agregaty, pojazdy firmowe
Zakres 2 Emisje pośrednie z zakupu energii Energia elektryczna, cieplna, chłodnicza

Architektura przygotowana na przyszłą rozbudowę o Zakres 3 (15 kategorii wg GHG Protocol — łańcuch dostaw, transport, odpady, podróże służbowe).

2. Podstawa metodologiczna

2.1. GHG Protocol — zasada obliczania emisji

Emisja CO₂e [kg] = Zużycie [jednostka] × Wskaźnik emisyjny [kg CO₂e / jednostka]
Przykład — Zakres 1
Zużycie: 500 litrów ON  ×  Wskaźnik ON: 2,62 kg CO₂e/litr  =  1 310 kg CO₂e = 1,31 t CO₂e
Przykład — Zakres 2
Zużycie: 10 000 kWh  ×  Wskaźnik KOBIZE (2024): 0,685 kg CO₂e/kWh  =  6 850 kg CO₂e = 6,85 t CO₂e

2.2. KOBIZE — źródło wskaźników emisyjnych

KOBIZE (Krajowy Ośrodek Bilansowania i Zarządzania Emisjami, IOŚ-PIB) corocznie publikuje wskaźniki emisyjności dla energii elektrycznej.

  • System jest fabrycznie zasilony aktualnymi wskaźnikami KOBIZE + GHG Protocol
  • Aktualizacja przez import XML pobranego ze strony kobize.pl
  • Ręczne dodawanie własnych wskaźników przez Managera
  • Każdy wskaźnik jest wersjonowany (z polami validFrom–validTo) — zmiana nie modyfikuje historycznych obliczeń

2.3. Otoczenie regulacyjne UE

System przygotowuje firmę do zgodności z:

  • CSRD (Corporate Sustainability Reporting Directive) — obowiązek raportowania ESG
  • ESRS E1 (Climate Change) — 9 wymogów ujawnieniowych, w tym emisje Scope 1 i 2
  • NFRD — poprzedniczka CSRD (dyrektywa o sprawozdawczości niefinansowej)

Raporty generowane przez system są strukturyzowane zgodnie z ESRS E1: dane zagregowane w tonach CO₂e, podział Scope 1 / Scope 2, porównania okres-do-okresu, metodologia location-based dla Scope 2.

4.2. Kluczowa zasada: wersjonowanie wskaźników

Wpis emisyjny zawsze przechowuje snapshot wskaźnika użytego w momencie kalkulacji. Dzięki temu:

  • Aktualizacja wskaźnika przez KOBIZE (co rok) nie zmienia historycznych obliczeń
  • Każdy wpis jest odtwarzalny i audytowalny
  • Można zidentyfikować, którą wersją wskaźnika posłużono się dla danego okresu

Mechanizm wersjonowania — przykład

5.4. Faktury i wpisy

Funkcja: Główne narzędzie wprowadzania danych emisyjnych. Trzy ścieżki: ręczne dodawanie, import plików (XML/CSV/XLSX), import faktur KSeF. Jedna faktura może generować wiele wpisów emisyjnych.

Flow importu plików

KrokOpis
1 Upload pliku
CSV/XLSX → kreator mapowania kolumn | XML (KSeF/KOBIZE) → automatyczne parsowanie wg schematu FA(3)
2 Walidacja (dry run)
Sprawdzenie typów, kompletności, zgodności jednostek, istnienia źródeł w systemie. Raport błędów z listą wierszy.
3 Podgląd przed importem
Tabela z przeliczonym CO₂e. Możliwość ręcznej korekty pojedynczych wierszy lub odrzucenia pliku.
4 Zapis do bazy
Poprawne wiersze → status "Szkic" (lub "Zweryfikowany" dla Managera). Błędne wiersze → pominięte, raport do pobrania.

Import XML z KSeF (FA(3))

  • System parsuje strukturę FA(3) obowiązującą od 01.02.2026
  • Wyodrębnia pozycje faktury (nazwa towaru/usługi, ilość, jednostka, cena)
  • Automatycznie próbuje przypisać pozycje do źródeł emisji na podstawie słownika
  • Manager może ręcznie skorygować przypisania przed zatwierdzeniem

5.5. Raporty

Funkcja: Generowanie raportów okresowych w formatach PDF, XLSX i CSV.

Parametry raportu

ParametrOpcje
Typ raportuMiesięczny / Kwartalny / Roczny / Niestandardowy
OkresOd–do (dla miesięcznego: wybór miesiąca i roku)
ZakresScope 1 / Scope 2 / Oba
FormatPDF / XLSX / CSV
GrupowanieWg źródła / wg miesiąca / wg zakresu

Zawartość raportu PDF

  1. Strona tytułowa: nazwa firmy, tytuł, okres, data wygenerowania, osoba generująca
  2. Podsumowanie: Scope 1 [t CO₂e], Scope 2 [t CO₂e], Razem, zmiana % vs poprzedni okres
  3. Tabela szczegółowa: źródło → ilość → jednostka → wskaźnik → CO₂e [kg] → CO₂e [t], podział Scope 1/2, sumy częściowe
  4. Wykres kołowy: udział % Scope 1 vs Scope 2
  5. Metodologia: zastosowane wskaźniki (KOBIZE, GHG), metoda location-based dla Scope 2
  6. Stopka: numer strony, data, "Wygenerowano automatycznie"

5.6. Administracja

Funkcja: Zarządzanie użytkownikami i dziennik audytu. Dostępne tylko dla Managera.

Proces zapraszania pracownika

  1. Manager klika "Zaproś pracownika" → wpisuje e-mail
  2. System generuje unikalny token (JWT, ważny 48h) i wysyła e-mail
  3. Pracownik klika link → formularz: imię, nazwisko, hasło (min. 8 znaków, 1 wielka litera, 1 cyfra)
  4. Konto aktywowane → pracownik może się zalogować

Dziennik audytu

Tabela tylko do odczytu: data, użytkownik, akcja (CREATE/UPDATE/DELETE/LOGIN), encja, ID, szczegóły zmiany. Filtry: data, użytkownik, typ akcji. Eksport do CSV.

6. Przepływy danych — scenariusze

Scenariusz A: Ręczne dodanie zużycia paliwa (Scope 1)

#Akcja
1Pracownik loguje się, wchodzi w "Faktury i wpisy" → "Dodaj ręcznie"
2Wypełnia dane nagłówkowe (data, notatka "Tankowanie – listopad 2026")

5Manager weryfikuje → zmienia status na "Zweryfikowany"
6Wpis widoczny na Dashboardzie i w Raportach

Scenariusz B: Import faktury z KSeF XML (Scope 1 + 2)

#Akcja
1Manager pobiera XML z KSeF → "Importuj plik" w aplikacji
2System rozpoznaje format FA(3), parsuje numer faktury, datę, pozycje
3Auto-mapowanie: "Olej napędowy 500L" → źródło "Zbiornik ON – hala A", "Energia elektr. 2000 kWh" → "Licznik główny"
4Manager koryguje przypisanie energii na "Licznik hala B" (ręczna poprawka)
5Zatwierdza → 1 faktura, 2 wpisy emisyjne (Zweryfikowane)
6Dane na Dashboardzie

Scenariusz C: Aktualizacja wskaźników z KOBIZE XML

#Akcja
1KOBIZE publikuje nowe wskaźniki (grudzień 2026) → Manager pobiera XML
2"Współczynniki emisji" → "Import z KOBIZE" → upload XML
3System parsuje: "Energia elektr. PL" → nowa wartość 0,642, validFrom 01.01.2027
4Podgląd: stara 0,685 → nowa 0,642. Manager zatwierdza
5Wpisy od 01.01.2027 używają 0,642. Historyczne z 2026 zachowują 0,685

Scenariusz D: Import danych z WF-MAG (Scope 1)

#Akcja
1Pracownik eksportuje dane z WF-MAG do CSV → "Importuj plik"
2Kreator mapowania: kolumna A→Data, B→Pojazd, C→Paliwo, D→Ilość L
3Zapisuje szablon jako "WF-MAG standard" (do ponownego użycia)
4Dry run → 0 błędów → Import → wpisy "Szkic"
5Manager weryfikuje i zatwierdza
